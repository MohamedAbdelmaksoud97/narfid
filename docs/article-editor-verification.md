# نتائج التحقق من محرر المقالات

التحقق النهائي: 14 أكتوبر 2026. اختبارات المتصفح شُغّلت على نسخة `next build` ثم `next start` على `http://127.0.0.1:3015`، باستخدام Playwright 1.64.0 وChromium الفعلي في الوضع headless. استخدمت مشروع Supabase الحالي وحساب مجلس إدارة موجودًا؛ لم تستخدم بيانات وهمية أو API بديلًا.

## تجربة إنشاء المقال في Chromium

1. رفض إنشاء مقال دون جلسة، ثم تسجيل الدخول من الواجهة بحساب مجلس إدارة فعلي.
2. إنشاء مسودة، وكتابة عنوان وملخص ورابط ومحتوى عربي وإنجليزي؛ انتظار الحفظ التلقائي والتحقق من البيانات في Supabase.
3. تجربة الرجوع بالمتصفح ورابط العودة أثناء وجود تعديل غير محفوظ، وإلغاء المغادرة؛ إعادة تحميل المقال والتحقق من استعادة المحتوى المحفوظ.
4. البحث والاستبدال، تنسيق النص باختصار لوحة المفاتيح، إدراج جدول وإضافة صف.
5. رفع صورة محتوى وصورة غلاف إلى Storage، وإضافة الوصف البديل وتعليق الصورة؛ التأكد من منع الزائر من الوصول إلى صور المسودة.
6. تبديل RTL/LTR، وفتح المعاينة، وفحص عدم وجود تجاوز أفقي عند عرض 390 بكسل.
7. نشر المقال، والتحقق من HTML العام وSEO وJSON-LD وتعليق الصورة وإتاحة صور النسخة المنشورة.
8. تعديل المقال مع الحفظ التلقائي؛ التأكد من بقاء التعديل خاصًا حتى الضغط على «نشر التحديث».
9. إلغاء النشر؛ التأكد من اختفاء المحتوى العام، ووجود `noindex`، ومنع الوصول العام إلى الصور.
10. العودة إلى قائمة المقالات والتحقق من ظهور المقال الذي أُنشئ، ثم إنشاء مقال ثانٍ بمعرّف مستقل وحقول فارغة صحيحة.

لم تُسجّل التجربة أخطاء JavaScript أو رسائل `console.error`. حُفظت لقطات المحرر في `.private/article-qa/editor-desktop.png` و`.private/article-qa/editor-mobile.png`، وفُحصت بصريًا. هذه اللقطات محلية ومستثناة من Git.

أثناء التطوير، أصلحت التجارب مشكلات الرجوع مع cache الصفحات في Next، وتحديث القائمة عند العودة إليها، وبقاء زر الإنشاء في حالة انتظار، وتكرار معرّفات الحقول عند الاحتفاظ بأكثر من محرر داخل Activity. الاختبار النهائي يشمل هذه الحالات.

## البيانات والصلاحيات

الاختبار الثاني أنشأ مستخدمًا مؤقتًا خارج مجلس الإدارة مع `user_metadata` مضللة. أكّد أن RLS يمنعه من قراءة المسودات أو إنشاء المقالات أو منح نفسه عضوية أو إنشاء منشور أو رفع ملف مباشرة إلى Storage أو استخدام دالة النشر. الكتابة المجهولة مرفوضة أيضًا.

اختبار HTTP الإضافي تحقّق من رفض تعارض `revision` برمز 409، وطلبات المصدر الخارجي برمز 403، والمحتوى غير الآمن والصور المزيفة برمز 400. كما تحقّق من أن صورة جديدة في مسودة مقال منشور تبقى خاصة.

بعد انتهاء التجربة، أظهر فحص قاعدة البيانات:

| البيانات | العدد |
| --- | --- |
| المقالات التجريبية المتبقية | 0 |
| النسخ المنشورة المتبقية | 0 |
| مستخدمو الاختبار المؤقتون | 0 |
| ملفات bucket المقالات المتبقية | 0 |
| أعضاء مجلس الإدارة النشطون | 5 |

الـmigration مسجل باسم `nerved_articles` وإصدار `20261013193254`، مطابقًا لملف المشروع. بيانات الاختبار نُظّفت، ولم تُحذف حسابات مجلس الإدارة أو التصنيفات.

## نتائج الأدوات وحدود الفحص

فحص Supabase الأمني لم يُظهر ملاحظات على جداول المقالات أو RLS أو دوال النشر. الملاحظة الموجودة تخص إعداد Auth السابق: `auth_leaked_password_protection`.

سجّل `npm audit` تسع ملاحظات عالية في سلسلة أدوات shadcn/ESLint المرتبطة بـ`fast-glob` و`micromatch` و`braces`. اقتراح الإصلاح الآلي المتاح كان يتضمن تخفيضات رئيسية للحزم؛ لم يُنفّذ `npm audit fix --force`. اجتياز الفحوص الوظيفية لا يعني معالجة هذه الملاحظات الخاصة بالأدوات.

المتصفح المختبر Chromium؛ لم يُختبر Safari أو Firefox. الاختبار يتحقق من عدم تسريب المسودة ومن `noindex` للمقال غير المتاح؛ قد تكون حالة HTTP هي 200 بعد بدء البث وفق سلوك [Next.js not-found](https://nextjs.org/docs/app/api-reference/file-conventions/not-found). بقيت الخيارات غير المطلوبة، مثل التعاون الحي وسجل النسخ والعمل دون اتصال، خارج النطاق.

التوثيق الكامل للميزات والحزم والمهارات والبيئة في [article-editor.md](./article-editor.md). مرجع القالب المستخدم: [Tiptap Simple Editor](https://tiptap.dev/docs/ui-components/templates/simple-editor).

## إعادة التشغيل

أضيف `tests/browser/image-layout.spec.ts` لتغطية محاذاة الصورة بقياس موضعها الفعلي، والكتابة بجانبها، والحفظ وإعادة التحميل، والمعاينة والنشر، والـplaceholder في RTL/LTR. شُغّل على Chromium ونسخة الإنتاج ونجح في 25.6 ثانية بعد تصحيح تعارض خصوصية قواعد CSS على الموبايل. دورة المقال العامة واختبار RLS نجحا أيضًا أثناء هذه المراجعة. لقطتا النتيجة في `.private/article-qa/image-wrap-editor.png` و`.private/article-qa/image-wrap-public.png`؛ بيانات هذا الاختبار تُحذف وفق معرّف المقال الذي أنشأه فقط.

بعد تشغيل نسخة الإنتاج محليًا:

```powershell
$env:AUTH_TEST_BASE_URL='http://127.0.0.1:3015'
npm run test:articles:browser
npm run test:articles:http
node --env-file=.env.local scripts/verify-article-build.mjs
```

لا تُضف بيانات الدخول إلى الاختبارات؛ تُقرأ محليًا من الملف الخاص الموجود.
