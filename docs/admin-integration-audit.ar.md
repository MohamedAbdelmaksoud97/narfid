# مراجعة ترابط لوحة إدارة نرفد

تاريخ المراجعة: 18 أكتوبر 2026. النطاق: مشروع `narfid` ولوحة الإدارة وقاعدة بياناتها؛ مشروع GO مرجع ولا توجد تغييرات فيه.

## الإصلاحات الفعلية

| الملاحظة | أثرها قبل الإصلاح | السلوك بعد الإصلاح |
| --- | --- | --- |
| الخلط بين تعديل ملف العميل وأرشفته | إرسال الملف الكامل، الذي يحتوي `archived`، كان قد يحفظ علم الأرشفة وحده ويتجاهل الاسم والخطة وبقية التعديلات. | طلب الأرشفة مستقل بحقل واحد، وتعديل الملف يحفظ حقول المؤسسة والخطة والمسؤول. اختُبر تعديل العميل المحتمل والمتعاقد وإعادة تحميلهما. |
| اختلاف شرط دخول الصفحة عن شرط استخدام API | بعض الصفحات كانت تعتمد على بيانات الدور في Auth دون مراجعة العضوية النشطة في الجدول. | الدخول والصفحات تفحص العضوية الفعلية. ملفات التسويق تستخدم نفس فحص الوصول، مع تمييز رفض الصلاحية عن تعذر الاتصال. |
| الصفحة الرئيسية غير مكتملة | لم تعرض اختصارات العملاء والباقات، وكان وصف مكتبة التسويق قديمًا. | تعريف واحد للأقسام يغذي السايد بار ومسار الصفحة واختصارات الصفحة الرئيسية، مع وصف متسق. |
| إعادة العقد الموقّع إلى مسودة | كان يمكن لمستخدم الإدارة محاولة إعادة العقد إلى حالة قابلة للحذف. | قاعدة البيانات تمنع الرجوع إلى المسودة، والواجهة تعرض الحالات المناسبة للعقد المحفوظ. |
| حذف بيانات تابعة لملف مؤرشف عبر Data API | التحقق في التطبيق وحده لم يكن يكفي لتطبيق القراءة فقط عند الحذف المباشر. | Trigger يمنع حذف البيانات التابعة للأرشيف. الاستعادة تعيد إمكانية الإدارة، وتظل سجلات التحصيل محمية من الحذف. |
| توقيع مسودة بعد إيقاف باقتها | قد تكون الباقة متاحة وقت إنشاء العرض، ثم تُوقف قبل توقيعه. | تعاد مراجعة إتاحة الباقة عند توقيع المسودة. العقود الموقّعة السابقة تحتفظ بتفاصيلها. |
| تعديل بيانات بعد فشل تحديثها | قد يظل المستخدم أمام نسخة قديمة مع أزرار تعديل فعالة. | عمليات التعديل تتوقف في أقسام CRM والباقات حتى تنجح إعادة تحميل البيانات. اختُبر انقطاع تحميل الباقات والتعافي منه. |
| انتظار غير محدود في طلبات محرر المقالات | تعطل الشبكة قد يترك حفظًا أو رفعًا منتظرًا بلا نهاية. | مهلة اتصال لطلبات المحرر، ومهلة أطول لرفع الصور، وحد زمني لاتصالات جلسة المقالات، ورسالة تحفظ وضوح حالة العمل. |
| طلبات تحقق متكررة | تحميل الملفات المحمية كان قد يعيد فحص العضوية داخل الطلب نفسه، كما كانت بعض قراءات ملف العميل متسلسلة. | توحيد فحص التسويق وتجميع القراءات المستقلة لملف العميل بالتوازي، مع بقاء التحقق لكل طلب مستقل. |

## الروابط التي تمت مراجعتها

| المسار التشغيلي | ما تم التحقق منه |
| --- | --- |
| باقة ← عميل محتمل ← تعاقد ← عميل | القائمة في الإدخال والتعديل، حفظ معرف الباقة، التحويل مع التاريخ وجهات الاتصال، وعدم إنشاء تحويل جزئي. |
| الباقة ← العقد | تعبئة السعر والتجهيز والمميزات، السماح بقيمة اتفاق مخصصة، وحفظ اسم الباقة ومميزاتها والمبالغ السابقة عند تعديل الكتالوج. |
| العقد ← الدفعات ← التجديد | هللات صحيحة، دفعات جزئية، منع تجاوز المتبقي، إلغاء تسجيل الدفعة بسبب واضح، منع تغيير سجل التحصيل أو حذف العقد الموقّع، ومسودة تجديد مستقلة. |
| العميل ← التجهيز والتشغيل والدعم | قائمة التجهيز وإكمال المهام، جهات الاتصال، مرجع قاعدة البيانات وروابط النظام، طلبات الدعم، والأرشفة والاستعادة وسجل النشاط. |
| المهام الرئيسية ← المهام الفرعية | الإضافة والتعديل والحذف والإكمال وحفظ التقدم، ورفض التعديلات القديمة والحسابات غير المخوّلة. |
| المقال ← المسودة ← النسخة العامة | الحفظ التلقائي، حماية التعديلات عند التنقل، الصور الخاصة، التنسيق والاتجاه والالتفاف حول الصور، والنشر وإلغاء النشر. |
| السوشيال ← التصنيف ← حالة المنشور ← التحميل | حالة نشر مشتركة عبر الحسابات، عدم تأثر منصة بتعديل أخرى، الحذف والاستعادة، رفض التعديل القديم، وحماية الصور وحزم التحميل. |
| الإدارة ← الهوية والتسويق والسيو | ظهور الأقسام في نفس الإطار، روابط صحيحة، عنوان واضح وقسم نشط صحيح، وعرض سليم على الموبايل. |

## الصلاحيات والبيانات

- فحص عضوية نشطة عند الدخول والوصول للصفحات الخاصة وواجهات البيانات؛ بيانات المستخدم القابلة للتحرير لا تمنحه دور الإدارة.
- RLS مفعّل على الجداول العامة الـ17 وقت الفحص. وجود سياسات قراءة عامة للتصنيفات أو نسخ المقالات المنشورة مقصود؛ المسودات وCRM والمهام والتتبع الإداري خاصة بالمجلس.
- رفض طلبات الزوار والحسابات خارج المجلس، والتحقق من مصدر طلب التعديل وحجم المدخلات ومعرفات السجلات وإصداراتها.
- مخزن صور المقالات خاص، بحد 5 ميجابايت للصورة، والتحقق من نوع الصورة وبياناتها. الصور غير المنشورة ليست متاحة للزائر.
- ملفات `.env` و`.private` ليست ضمن الملفات المتتبعة في Git وقت الفحص.
- توجد أربعة تعريفات باقات وخمسة أعضاء نشطين. لا تُحذف بيانات المستخدمين ضمن الاختبارات؛ fixtures محددة تُنظف بمعرفاتها، واختبارات SQL تستخدم rollback.

## التحقق المنفذ

- اختبارات Auth الخمسة واختبارات المقالات والمهام والتسويق وCRM الـ25.
- نجح 12 سيناريو Chromium لدورات العملاء والباقات والمهام والمقالات والصور والتسويق، إضافة إلى المرور على كل أقسام الإدارة وتعطل تحديث الباقات والتعافي، باحتساب الإعادات المركزة.
- جميع صور المنشورات الـ232 وحزم المنصات والحزمة الكاملة، مع فحص الحماية والترويسات والأبعاد. فحص HTTP يعمل بدفعات محدودة ويحافظ على اختبار كل صورة.
- معاملات SQL: `crm.sql` و`crm-plans.sql` و`crm-board-directory.sql` و`crm-operational-guards.sql`.
- Lint وTypeScript وبناء الإنتاج. يُحفظ أثر الاختبارات محليًا في `test-results` و`.private`.

شهدت المحاولة الشاملة الأولى انتهاء مهلة اختبار المقالات، وانتهاء مهلة الفحص التسلسلي لجميع صور التسويق. نجحت إعادة اختبار المقالات بشكل مركز خلال 48 ثانية، ونجحت إعادة فحص الصور خلال نحو دقيقة و40 ثانية بعد تحويله إلى دفعات محدودة دون تقليل عدد الصور أو شروط التحقق.

## نقاط خارج الأتمتة الحالية

1. **إعداد أمني في Supabase:** Advisor أعاد تحذير `auth_leaked_password_protection` لأن منع كلمات المرور المسرّبة غير مفعّل. توثيق Supabase يضع هذه الخاصية في Pro وما فوق؛ تفعيلها قرار إعداد لخطة المشروع. [مرجع Supabase](https://supabase.com/docs/guides/auth/password-security).
2. **الإطلاق والقياس:** حسب آخر معلومات المالك، الدومين النهائي وSearch Console وAnalytics لم تُجهز بعد. قسم SEO يشرح الخطوات؛ بيانات أداء حقيقية تبدأ بعد الربط والإطلاق.
3. **كتالوج الإدارة والعروض العامة:** الباقات في الإدارة مصدر اختيار العميل وإعداد عقده. تحديث أسعار أو عروض الموقع العام يمر بمراجعة المحتوى المنشور؛ تعديلات الكتالوج الداخلي لا تُنشر كعرض عام تلقائيًا.
4. **التنفيذ والتحصيل والتواصل:** CRM يسجل حالة التشغيل والتحصيل ومواعيد المتابعة؛ إرسال التنبيهات، التحصيل المصرفي، النشر الاجتماعي، ونشر أنظمة العملاء وإدارة النسخ الاحتياطية الفعلية عمليات خارج الأتمتة الحالية. المبالغ سجلات إدارية وليست فواتير ضريبية أو خصمًا بنكيًا.
5. **أنواع المهام:** المهام العامة خطة عمل الشركة، ومتابعات CRM مرتبطة بعلاقة عميل وتجهيزه. لكل منهما غرض وسجل مستقل؛ لا يوجد نسخ تلقائي يولّد مهمتين لنفس الإجراء.

المراجعة تثبت السلوك في السيناريوهات المنفذة وفحص الكود والصلاحيات المذكورة؛ متابعة الأعطال واختبار تغيرات البيئة والبيانات تبقى جزءًا من التشغيل المستمر.
