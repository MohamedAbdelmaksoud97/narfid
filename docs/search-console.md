# ربط Google Search Console بنرفد

أضيف الربط في 9 نوفمبر 2026 إلى `/board/seo` باستخدام تصميم اللوحة القائم وshadcn، وفق موافقة المالك على المتابعة دون ملف UI-system المفقود. لا ينشئ الربط حساب Google أو يغيّر صلاحيات الموقع؛ إكماله يتطلب موافقة الحساب من زر «ربط Google Search Console».

## الوظائف

- تقارير بحث الويب للبيانات النهائية: النقرات، الظهور، CTR ومتوسط موضع الظهور.
- فترة 28 يومًا دون اليوم الحالي، ومقارنتها بالأيام الـ28 السابقة. تواريخ Search Console بتوقيت المحيط الهادئ؛ وقت السحب معروض بتوقيت القاهرة.
- فلتر السعودية أو جميع البلدان، وأعلى 20 نتيجة للكلمات والصفحات والأجهزة، وتفصيل الأيام التي أعادها Google. الإجماليات تُطلب مستقلة عن جداول أعلى النتائج؛ جمع الجداول لا يمثل إجمالي الموقع.
- حالة فهرسة رابط عام عبر URL Inspection، بما فيها التغطية وآخر زحف والروابط الأساسية. الفحص يقرأ نسخة Google المحفوظة ولا ينفذ Live Test أو طلب فهرسة.
- إعادة استخدام تقرير محفوظ لمدة 6 ساعات، ثم تحديثه عند فتح الصفحة. التحديث اليدوي لا يعيد الطلب خلال أول دقيقة. لا توجد مهمة Cron تعمل دون زيارة الصفحة.
- البيانات غير المتاحة تظهر كحالة انتظار، لا صفرًا. يبقى آخر تقرير ظاهرًا مع تحذير وتاريخ السحب إذا تعذر التحديث؛ إلغاء التفويض يتطلب إعادة الربط.

## إعداد العميل

يحتاج خادم Vercel في بيئة Production إلى `SUPABASE_SECRET_KEY`، بالإضافة إلى متغيرات Supabase العامة المستخدمة أصلًا في تسجيل الدخول. تُنسخ قيمة المفتاح من `.env.local` مباشرة إلى إعدادات المشروع في Vercel، دون بادئة `NEXT_PUBLIC_`، ثم يُعاد النشر. يجب أن تكون القيمة نفسها التي استُخدمت عند استيراد العميل المشفّر؛ إنشاء مفتاح مختلف لا يفتح البيانات السابقة.

ملف OAuth الأصلي موجود محليًا فقط في `.private/google-search-console-oauth.json`، وليس داخل `public` أو Git. اسم مشروع Google: `narfid-seo`. يجب تفعيل Google Search Console API وإتاحة الحساب ضمن Test users إذا كان التطبيق في وضع Testing.

عنوان العودة المسجل والمنفّذ:

```text
https://www.narfid.com/api/board/seo/google/callback
```

الصلاحية الوحيدة المطلوبة:

```text
https://www.googleapis.com/auth/webmasters.readonly
```

بعد تطبيق migration `20261109213135_narfid_search_console.sql`، يستورد الأمر التالي بيانات العميل مشفّرة. إعادة الأمر لا تغيّر تفويضًا قائمًا إذا كان العميل نفسه، وترفض استبدال عميل مختلف ضمنيًا:

```text
npm run seo:google:configure
```

يدخل عضو مجلس الإدارة إلى صفحة SEO ويضغط زر الربط، ثم يختار الحساب المالك للموقع أو صاحب صلاحية مستخدم كامل على `https://www.narfid.com/`. تُتحقق صلاحية الموقع قبل حفظ رمز التجديد. لا يُطلب إذن بريد أو ملف شخصي أو صلاحية كتابة.

حالة Testing الخارجية تُصدر عادة رمز تجديد ينتهي بعد 7 أيام لهذه الصلاحية. راجع إعداد نشر تطبيق Google ومتطلبات المراجعة قبل الاعتماد على تفويض دائم؛ الواجهة تعرض الحاجة لإعادة الربط عند انتهاء التفويض.

## حفظ البيانات والصلاحيات

- `seo_google_connections`: عميل OAuth ورمز التجديد مشفّران بـAES-256-GCM؛ لا تُعاد قيمهما إلى المتصفح. مفاتيح منفصلة بالغرض تمنع تبادل بيانات العميل ورمز التجديد وملف حالة OAuth.
- `seo_google_reports`: تقرير لكل بلد مرتبط بجيل الاتصال، لمنع إظهار بيانات تفويض سابق بعد إعادة الربط أو الفصل.
- الجدولان تحت RLS، دون منح للزائر أو `authenticated` ودون سياسات تسمح لهما بالوصول. الوصول من عميل `service_role` على الخادم فقط؛ تنبيهات `rls_enabled_no_policy` المعلوماتية مقصودة لهذين الجدولين.
- كل مسار API يعيد فحص المستخدم عبر Auth وعضويته الفعالة في `board_members`. طلبات POST تتطلب Origin صحيحًا، وحجمًا محدودًا وJSON.
- حالة OAuth عشوائية ومشفّرة داخل Cookie من نوع HttpOnly، مربوطة بالعضو وجيل الاتصال، صالحة لعشر دقائق، مع PKCE. تُمسح عند عودة Google. لا تُسجل رموز Google أو أسرار العميل أو رسائل المزود الخام.
- تُشتق مفاتيح التشفير بـHKDF من `GOOGLE_SEARCH_CONSOLE_ENCRYPTION_KEY` إن عُيّن، وإلا من `SUPABASE_SECRET_KEY` الموجود على الخادم. يجب أن يطابق مفتاح الاستيراد المحلي مفتاح الاستضافة. تغيير مفتاح Supabase عند استخدامه للتشفير يحتاج خطة لإعادة تشفير الاتصال بالمفتاح القديم، أو إعادة إعداد العميل والتفويض؛ لا تبدله منفردًا دون هذه الخطوة.
- فصل الربط يمسح التفويض المحلي ويحاول إلغاءه لدى Google. إذا فشلت خطوة Google، تُبلغ الواجهة بأن إلغاء إذن الحساب لم يتأكد. إعداد GA4 مستقل.

## المسارات والتحقق

إذا أعاد المسار خطأ `not_configured` ورسالة «إعداد اتصال Google على الخادم غير مكتمل»، فتحقق أولًا من `SUPABASE_SECRET_KEY` في بيئة الاستضافة وأعد النشر بعد إضافته. أما رسالة تعذر فتح بيانات الاتصال فتحتاج مطابقة مفتاح التشفير المحلي مع الخادم.

- `GET /api/board/seo/google?country=sau|all`: حالة الاتصال والتقرير المتاح.
- `POST /api/board/seo/google`: تحديث التقرير أو فحص رابط عام أو فصل الربط.
- `POST /api/board/seo/google/connect`: بدء تفويض قراءة فقط.
- `GET /api/board/seo/google/callback`: معالجة عودة Google وربطها بالجلسة الحالية.

`npm run test:seo:google` يختبر التشفير وCSRF/PKCE وحدود الروابط والفترات والبيانات الناقصة ومعالجة أخطاء Google بمزود وهمي. اختبار المتصفح `tests/browser/search-console.spec.ts` يفحص حماية المسارات وRLS وحالات رفض OAuth دون منح صلاحية Google، ويستخدم بيانات اختبار صريحة لاختبار العرض والفلاتر والجوال. الاختبارات لا تثبت موافقة Google أو وجود بيانات حقيقية؛ هاتان الخطوتان تظهران من الاتصال الفعلي بعد موافقة المالك.

نجح التحقق المحلي على نسخة الإنتاج: TypeScript وESLint والبناء، و30 اختبارًا تشمل الربط والدومين والمقالات والحملة والمتصفح. فُحص العرض بصريًا على الكمبيوتر والجوال، وتأكد الفحص من عدم وجود أسرار Google أو Supabase في ملفات المتصفح أو التغييرات المرفوعة. تطبيق schema واستيراد العميل لا يثبتان توفر مفتاح الخادم في Vercel؛ يُراجع المسار المحمي على الإنتاج بعد ضبط البيئة.
