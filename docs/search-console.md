# ربط Google Search Console بنرفد

أضيف الربط في 9 نوفمبر 2026 إلى `/board/seo` باستخدام تصميم اللوحة القائم وshadcn، وفق موافقة المالك على المتابعة دون ملف UI-system المفقود. لا ينشئ الربط حساب Google أو يغيّر صلاحيات الموقع؛ إكماله يتطلب موافقة الحساب من زر «ربط Google Search Console».

## حالة التشغيل — 10 نوفمبر 2026

اكتملت موافقة الحساب والاتصال الفعلي بملكية URL-prefix `https://www.narfid.com/`، وأكد فحص API المصادق عليه `configured: true` و`connected: true` دون خطأ أو حاجة لإعادة الربط وقت الفحص. لا تكرر الإعداد لمجرد غياب بيانات الأداء.

أكدت لقطة المالك نجاح الخريطة وقراءة 71 رابطًا، وأثبت URL Inspection فهرسة الرئيسية؛ تقرير Pages الكامل ما زال يعالج البيانات حسب لقطة المالك. آخر تقرير أداء مفحوص ينتهي في 8 نوفمبر، قبل الإطلاق، ولا يعيد إجماليات أو صفوفًا للسعودية أو جميع البلدان. هذه بيانات غير متاحة، وليست صفر نقرات أو دليلًا على فشل الربط.

ظهر معرّف GA4 على الإنتاج وأكد المالك ظهور زيارة في Realtime. اكتملت لاحقًا موافقة Analytics للخاصية `563435056`، ونجحت قراءة التقارير الفعلية مع استمرار اتصال Search Console. نتائج الاختبار وحدوده أدناه؛ الحالة الحية تُقرأ من تبويبي التقارير.

## فحص فعلي بعد التفويض — 10 نوفمبر 2026

- نجحت تقارير GA4 وSearch Console للسعودية ولجميع البلدان بحالة HTTP 200 دون خطأ أو طلب إعادة ربط. تاريخي GA4 يغطي 13 أكتوبر–9 نوفمبر بتوقيت الرياض ولا يعيد صفوفًا بعد؛ Search Console يغطي 12 أكتوبر–8 نوفمبر بتوقيت المحيط الهادئ، قبل الإطلاق، ولا يعيد بيانات. لا تسجل الغياب كصفر.
- أعاد GA4 Realtime عند `2026-11-10T00:07:44Z` مستخدمًا نشطًا واحدًا و5 أحداث `page_view` وحدثين `demo_request_start`، دون صف `whatsapp_click`. فحص مباشر آخر عند `00:12:11Z` أعاد القيم نفسها. لم يظهر تفصيل للسعودية. هذه لقطة نافذة 30 دقيقة، وليست إجمالي زيارات أو طلبات فعلية أو دليلًا على مصدر بحث عضوي.
- اختُبرت الأزرار في متصفح جديد: لا طلبات جمع قبل الموافقة أو بعد رفضها؛ بعد قبولها أُرسلت أحداث طلب العرض وواتساب واستقبلت طلبات الجمع HTTP 204. لم يُرسل الاختبار رسالة واتساب. لم تضف زيارة `/login` أحداث جمع. هذا يثبت مسار الإرسال في العينة، ولا يثبت إدراج الحدث في التقارير؛ ظل واتساب غير ظاهر في أحدث استجابة Realtime.
- **تكرار يحتاج متابعة:** رُصد إرسال `page_view` مرتين في جلسة اختبار للصفحة نفسها، بينما احتوت قائمة أحداث كود الموقع على مشاهدة واحدة. أظهر ملف Google tag المنشور إعدادات History وForm وScroll وDownload وVideo مفعّلة؛ هذا مؤشر إعداد، وليس قراءة رسمية لحالة مفتاح Enhanced measurement. تحقق من إيقاف Enhanced measurement من حساب GA4 وأعد اختبار مشاهدة واحدة لكل تنقل.
- محاولة قراءة إعدادات الخاصية عبر Analytics Admin API أعادت 403 و`SERVICE_DISABLED`؛ Data API تعمل، وAdmin API خدمة منفصلة غير مفعّلة وقت الفحص. لم نغيّر إعدادات Google أو نطلب صلاحية تعديل. لا يلزم تفعيل Admin API لإيقاف Enhanced measurement يدويًا من الحساب.
- Search Console Sitemaps API أكدت الخريطة دون معالجة معلقة، و0 أخطاء و0 تحذيرات، و71 رابط ويب و58 صورة. آخر تنزيل `2026-11-09T20:57:48.835Z`. URL Inspection أكد فهرسة الرئيسية ومقال مخزون المنتجات؛ مقال المخزون زُحف إليه في `2026-11-09T23:24:12Z` بعد أن كان غير معروف في الفحص السابق. صفحة العضويات ومقال اختيار نظام الإدارة ما زالا مكتشفين دون زحف. هذه عينة من أربع صفحات وليست عدد المفهرس في الموقع.

المتبقي: إيقاف القياس المحسّن والتحقق من عدم التكرار، ثم متابعة ظهور واتساب في بيانات Google بعد تجربة بشرية مؤرخة ومراعاة تأخر المعالجة. قد تشمل التقارير نشاط المالك والفحوص؛ لا تعتبرها فرص مبيعات.

## إضافة Analytics إلى التفويض القائم

- أكّد المالك تجهيز Data API وقدّم Property ID `563435056`. افتح `/board/seo?tab=analytics` واضغط «ربط GA4»، ثم وافق بحساب له وصول إلى الخاصية وملكية الموقع. لا يلزم سر جديد أو عنوان callback جديد؛ تُستخدم بيانات العميل المشفرة ومسار العودة الموجودان.
- يطلب الربط الصلاحيتين `webmasters.readonly` و`analytics.readonly`. تبقى محاولة Search Console وحدها كما هي قبل إضافة Analytics؛ بعد التفويض المشترك، إعادة الربط تحتفظ بطلب الصلاحيتين. أي فشل في الموافقة أو فحص الوصول يترك الاتصال المحفوظ السابق كما هو.
- يتحقق callback من الصلاحيتين ومن الوصول الفعلي للموقع والخاصية قبل حفظ رمز التجديد المشفر وتغيير جيل الاتصال. لا يغيّر الربط Enhanced measurement أو يرسل أحداث قياس مصطنعة. **فصل Google يلغي التفويض المشترك للخدمتين**؛ لا تعرضه كفصل خدمة واحدة.
- `GET /api/board/seo/analytics?country=all|sau` يعرض آخر 28 يومًا دون اليوم الحالي ومقارنتها بالـ28 السابقة، وفق منطقة الخاصية التي يرجعها Google. الإجماليات مستقلة عن أعلى 20 صفحة وقناة؛ بيانات الفترة ترشّح `www.narfid.com` والمسارات العامة وتعرض فقط أسماء أحداث القياس المحددة. لا تُقرأ بيانات مستخدمين فردية أو روابط تحتوي استعلامات.
- `GET /api/board/seo/analytics?view=realtime&country=all|sau` يفحص المستخدمين النشطين وأحداث `page_view` و`whatsapp_click` و`demo_request_start` خلال آخر 30 دقيقة عند الطلب فقط. مخطط Realtime لا يدعم فلتر المسار نفسه؛ التقرير للخاصية كاملة مع فلتر البلد. لا تجمع عدد المستخدمين عبر الأحداث للحصول على الإجمالي.
- `POST /api/board/seo/analytics` مع `{ "action": "refresh", "country": "all" }` يحدّث التقرير. الوصول محمي بعضوية المجلس الحية وOrigin للطلبات المعدلة، وبنفس ترويسات الخصوصية. لا توجد جداول أو متغيرات استضافة جديدة.
- تُحفظ التقارير المجمعة في ذاكرة نسخة الخادم الدافئة فقط: 5 دقائق للتاريخي، دقيقة قبل التحديث اليدوي، و30 ثانية للحظي، مع تجميع الطلبات المتزامنة وفصلها بجيل الاتصال والبلد. هذه ذاكرة مؤقتة محدودة وليست حد طلبات موزعًا أو سجلًا دائمًا؛ إعادة تشغيل الخادم أو تعدد النسخ قد يعيدان الطلب.
- البيانات الناقصة تختلف عن صفر أعاده Google. غياب حدث عن الاستجابة لا يثبت تعطله، وتُعرض تحذيرات الخصوصية والعينة والاقتطاع إن أبلغ عنها المزود. الأحداث الحديثة قد لا تظهر في تقرير ينتهي أمس؛ استخدم الفحص اللحظي ثم Tag Assistant/DebugView لاختبار التكرار والموافقة بشكل مستقل.

التحقق الآلي: `node --import=tsx --test tests/analytics.test.ts tests/search-console.test.ts`، واختبارات المتصفح في `tests/browser/analytics.spec.ts` و`tests/browser/search-console.spec.ts`. بيانات العرض الوهمية تختبر الحالات فقط؛ نجاح التقارير الفعلية لا يُعلن قبل موافقة المالك واختبار API على الخاصية.

## الوظائف

- التقارير وفحص الروابط داخل تبويب «تقارير Google» مستقل عن تبويب «الدليل والخطة» في صفحة SEO. يفتح `?tab=google` التقارير مباشرة؛ روابط `#seo-google` القديمة وعودة OAuth تفتح التبويب تلقائيًا. يدعم التبديل الرجوع والتقدم في المتصفح دون إعادة تحميل الصفحة.
- تقارير بحث الويب للبيانات النهائية: النقرات، الظهور، CTR ومتوسط موضع الظهور.
- فترة 28 يومًا دون اليوم الحالي، ومقارنتها بالأيام الـ28 السابقة. تواريخ Search Console بتوقيت المحيط الهادئ؛ وقت السحب معروض بتوقيت القاهرة.
- فلتر السعودية أو جميع البلدان، وأعلى 20 نتيجة للكلمات والصفحات والأجهزة، وتفصيل الأيام التي أعادها Google. الإجماليات تُطلب مستقلة عن جداول أعلى النتائج؛ جمع الجداول لا يمثل إجمالي الموقع.
- حالة فهرسة رابط عام عبر URL Inspection، بما فيها التغطية وآخر زحف والروابط الأساسية. الفحص يقرأ نسخة Google المحفوظة ولا ينفذ Live Test أو طلب فهرسة.
- إعادة استخدام تقرير محفوظ لمدة 6 ساعات، ثم تحديثه عند فتح الصفحة. التحديث اليدوي لا يعيد الطلب خلال أول دقيقة. لا توجد مهمة Cron تعمل دون زيارة الصفحة.
- البيانات غير المتاحة تظهر كحالة انتظار، لا صفرًا. يبقى آخر تقرير ظاهرًا مع تحذير وتاريخ السحب إذا تعذر التحديث؛ إلغاء التفويض يتطلب إعادة الربط.

## إعداد العميل

يحتاج خادم Vercel في بيئة Production إلى `SUPABASE_SECRET_KEY`، بالإضافة إلى متغيرات Supabase العامة المستخدمة أصلًا في تسجيل الدخول. تُنسخ قيمة المفتاح من `.env.local` مباشرة إلى إعدادات المشروع في Vercel، دون بادئة `NEXT_PUBLIC_`، ثم يُعاد النشر. يجب أن تكون القيمة نفسها التي استُخدمت عند استيراد العميل المشفّر؛ إنشاء مفتاح مختلف لا يفتح البيانات السابقة.

ملف OAuth الأصلي موجود محليًا فقط في `.private/google-search-console-oauth.json`، وليس داخل `public` أو Git. اسم مشروع Google: `narfid-seo`. يجب تفعيل Google Search Console API وإتاحة الحساب ضمن Test users إذا كان التطبيق في وضع Testing.

عنوان العودة المسجل والمنفّذ:

```text
https://www.narfid.com/api/board/seo/google/callback
```

الصلاحية الأصلية لـSearch Console (ويضاف إليها `https://www.googleapis.com/auth/analytics.readonly` عند اختيار ربط GA4):

```text
https://www.googleapis.com/auth/webmasters.readonly
```

بعد تطبيق migration `20261109213135_narfid_search_console.sql`، يستورد الأمر التالي بيانات العميل مشفّرة. إعادة الأمر لا تغيّر تفويضًا قائمًا إذا كان العميل نفسه، وترفض استبدال عميل مختلف ضمنيًا:

```text
npm run seo:google:configure
```

يدخل عضو مجلس الإدارة إلى صفحة SEO ويضغط زر الربط، ثم يختار الحساب المالك للموقع أو صاحب صلاحية مستخدم كامل على `https://www.narfid.com/`. تُتحقق صلاحية الموقع قبل حفظ رمز التجديد. لا يُطلب إذن بريد أو ملف شخصي أو صلاحية كتابة.

حالة Testing الخارجية تُصدر عادة رمز تجديد ينتهي بعد 7 أيام لهذه الصلاحية. راجع إعداد نشر تطبيق Google ومتطلبات المراجعة قبل الاعتماد على تفويض دائم؛ الواجهة تعرض الحاجة لإعادة الربط عند انتهاء التفويض.

## حفظ البيانات والصلاحيات

- `seo_google_connections`: عميل OAuth ورمز التجديد مشفّران بـAES-256-GCM؛ لا تُعاد قيمهما إلى المتصفح. مفاتيح منفصلة بالغرض تمنع تبادل بيانات العميل ورمز التجديد وملف حالة OAuth.
- `seo_google_reports`: تقرير لكل بلد مرتبط بجيل الاتصال، لمنع إظهار بيانات تفويض سابق بعد إعادة الربط أو الفصل.
- الجدولان تحت RLS، دون منح للزائر أو `authenticated` ودون سياسات تسمح لهما بالوصول. الوصول من عميل `service_role` على الخادم فقط؛ تنبيهات `rls_enabled_no_policy` المعلوماتية مقصودة لهذين الجدولين.
- كل مسار API يعيد فحص المستخدم عبر Auth وعضويته الفعالة في `board_members`. طلبات POST تتطلب Origin صحيحًا، وحجمًا محدودًا وJSON.
- حالة OAuth عشوائية ومشفّرة داخل Cookie من نوع HttpOnly، مربوطة بالعضو وجيل الاتصال، صالحة لعشر دقائق، مع PKCE. تُمسح عند عودة Google. لا تُسجل رموز Google أو أسرار العميل أو رسائل المزود الخام.
- تُشتق مفاتيح التشفير بـHKDF من `GOOGLE_SEARCH_CONSOLE_ENCRYPTION_KEY` إن عُيّن، وإلا من `SUPABASE_SECRET_KEY` الموجود على الخادم. يجب أن يطابق مفتاح الاستيراد المحلي مفتاح الاستضافة. تغيير مفتاح Supabase عند استخدامه للتشفير يحتاج خطة لإعادة تشفير الاتصال بالمفتاح القديم، أو إعادة إعداد العميل والتفويض؛ لا تبدله منفردًا دون هذه الخطوة.
- فصل الربط يمسح التفويض المحلي ويحاول إلغاءه لدى Google. إذا فشلت خطوة Google، تُبلغ الواجهة بأن إلغاء إذن الحساب لم يتأكد. إعداد GA4 مستقل.

## المسارات والتحقق

إذا أعاد المسار خطأ `not_configured` ورسالة «إعداد اتصال Google على الخادم غير مكتمل»، فتحقق أولًا من `SUPABASE_SECRET_KEY` في بيئة الاستضافة وأعد النشر بعد إضافته. أما رسالة تعذر فتح بيانات الاتصال فتحتاج مطابقة مفتاح التشفير المحلي مع الخادم.

- `GET /api/board/seo/google?country=sau|all`: حالة الاتصال والتقرير المتاح.
- `POST /api/board/seo/google`: تحديث التقرير أو فحص رابط عام أو فصل الربط.
- `POST /api/board/seo/google/connect`: بدء تفويض قراءة فقط.
- `GET /api/board/seo/google/callback`: معالجة عودة Google وربطها بالجلسة الحالية.

`npm run test:seo:google` يختبر التشفير وCSRF/PKCE وحدود الروابط والفترات والبيانات الناقصة ومعالجة أخطاء Google بمزود وهمي. اختبار المتصفح `tests/browser/search-console.spec.ts` يفحص حماية المسارات وRLS وحالات رفض OAuth دون منح صلاحية Google، ويستخدم بيانات اختبار صريحة لاختبار العرض والفلاتر والجوال. الاختبارات لا تثبت موافقة Google أو وجود بيانات حقيقية؛ هاتان الخطوتان تظهران من الاتصال الفعلي بعد موافقة المالك.

نجح التحقق المحلي على نسخة الإنتاج: TypeScript وESLint والبناء، و30 اختبارًا تشمل الربط والدومين والمقالات والحملة والمتصفح. فُحص العرض بصريًا على الكمبيوتر والجوال، وتأكد الفحص من عدم وجود أسرار Google أو Supabase في ملفات المتصفح أو التغييرات المرفوعة. تطبيق schema واستيراد العميل لا يثبتان توفر مفتاح الخادم في Vercel؛ يُراجع المسار المحمي على الإنتاج بعد ضبط البيئة.
