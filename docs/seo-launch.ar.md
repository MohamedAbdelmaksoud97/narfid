# حالة تنفيذ SEO وخطوات إطلاق نرفد

تاريخ التنفيذ: 14 أكتوبر 2026. مشروع العمل `narfid`؛ استُخدم `go` كمرجع للوظائف واللقطات، دون تعديل ملفاته.

## المنفذ

- أصل موحد للروابط المطلقة والـcanonical وصور المشاركة والبيانات المنظمة. فحص صحة قيمة `NEXT_PUBLIC_SITE_URL` ومنع مسار أو بيانات دخول داخلها.
- `robots.txt` مرتبط بإعداد الفهرسة؛ المعاينات وlocalhost محجوبة. لا تُفتح الفهرسة بمجرد استخدام build إنتاجي.
- `sitemap.xml` للصفحات العامة والنسخ المنشورة فقط، مع `lastmod` من تعديل المحتوى العام؛ لا تاريخ تلقائي وهمي لكل زيارة، ولا مسودات أو روابط قديمة. القراءة بدفعات لتجاوز حد PostgREST الافتراضي.
- canonical مستقل لترقيم مكتبة المقالات، وبيانات المشاركة لكل صفحة.
- روابط المقالات المنشورة محفوظة في سجل؛ التحويل 308 من أي رابط قديم إلى الحالي مباشرة، دون سلسلة أو إعادة استعمال الرابط لمقال آخر. المعاينة قبل النشر لا تغيّر الرابط العام.
- حسم وجود المقال قبل بدء بث الصفحة؛ الرابط المفقود أو الملغى يعطي 404 وnoindex، وعطل القراءة يعطي 503 بدل ادعاء عدم وجوده.
- حماية المسودات والملاحظات والمراجعات عبر RLS. صور الأصل وكل المقاسات تمر بسياسات Storage مع no-store، وتختفي عن الزائر عند إلغاء النشر.
- صور WebP متجاوبة بمقاسات 320 و640 و960 و1440 و1920، وأبعاد للصور المرفوعة الجديدة. يبقى GIF بصيغته للحفاظ على الحركة.
- فهرس بعناوين ثابتة مشتقة من النص، وروابط داخلية قابلة للتنقل، ومقالات منشورة مرتبطة، وحل مناسب ودعوة للتواصل.
- هوية عامة لفريق نرفد، وOrganization وBreadcrumbList وArticle دون تقييمات أو نتائج أو اعتماد مختلق.
- موجز داخلي للمقال: سؤال القارئ والموضوع والنية والجمهور والملاحظات وموعد المراجعة. الحل المرتبط والكاتب جزء من النسخة المنشورة، أما بقية الموجز فخاص. معاينة بحث وتنبيهات تحريرية دون درجة SEO وهمية.
- تجهيز كود تحقق Google وGA4 الاختياري بعد الموافقة، مع مشاهدة الصفحات وبدء العرض وفتح واتساب. لم يُنشأ حساب أو تُرسل بيانات قياس فعلية، ولا يوجد حدث generate_lead لأن تدفق واتساب لا يؤكد استلام طلب.
- قسم SEO بالإدارة يعرض الإنجاز والخطوة الحالية والعدد الحقيقي للمقالات ومواعيد المراجعة والخطوات التالية.

اللقطات أصلية، فُحصت بصريًا قبل رفعها، وتستبعد شاشات أسماء الأعضاء والجوالات. يُوضح النص أنها من النظام المرجعي Go Fitness، أول عميل للنظام، وليست نتائج أداء أو بيانات تجارية لنرفد. الأرقام والأمثلة داخل المتن معلّمة كتوضيح. لا ادعاء بتكامل دفع أو اعتماد زاتكا أو مشتريات ووصفات غذاء متكاملة.

المقالات موجودة داخل جداول المقالات المعتادة ويمكن تعديلها وإلغاء نشرها من المحرر. مرجعها التحريري في `content/seo-articles.ar.mjs`. أمر `npm run seo:seed` يعيد المحاولة للمهمة غير المكتملة فقط، ولا ينشئ نسخًا مكررة أو يعيد نشر مقال سبق اكتماله ثم ألغى الفريق نشره. حالة الأمر داخل `.private` وليست بيانات اعتماد أو جزءًا من تطبيق المتصفح. موعد المراجعة الأول 14 يناير 2027 أو عند تغيير المنتج، أيهما أسبق.

## الترتيب التالي لصاحب المشروع

1. اختيار الدومين والاستضافة وتفعيل HTTPS، ومراجعة معلومات الشركة والنطاق التعاقدي وسياسة البيانات ومواد دراسة الحالة قبل الاستخدام التجاري.
2. وضع أصل الدومين النهائي في `NEXT_PUBLIC_SITE_URL` بإعدادات الاستضافة، دون مسار أو شرطة إضافية مطلوبة. إعادة البناء والنشر؛ لا تستخدم localhost في الإنتاج.
3. إبقاء `SITE_INDEXING_ENABLED=false` حتى فحص النسخة المنشورة. عند اعتمادها، ضبط `SITE_INDEXING_ENABLED=true` في الإنتاج فقط وإعادة النشر. الكود يمنع الفهرسة إذا كان أصل الرابط محليًا أو كانت بيئة Vercel معاينة. في أي استضافة أخرى اجعل إعداد المعاينة false صراحة.
4. فحص الرابط المفضل والتحويل من النسخ الأخرى، والصفحات والصور، و`/robots.txt` و`/sitemap.xml` وcanonical و404 على الدومين الحقيقي. تحويل المضيف يعمل عند فتح الفهرسة؛ راجع HTTPS وإعدادات reverse proxy مع الاستضافة لتجنب التحويل المتكرر.
5. إنشاء ملكية Domain في Search Console والتحقق عبر DNS. إذا استخدمت تحقق URL عبر meta بدلًا منه، ضع الرمز في `GOOGLE_SITE_VERIFICATION`. وجود الرمز في الموقع لا يثبت قبول Google للملكية.
6. إرسال خريطة الموقع وفحص الرئيسية والحلول ومقالين عبر URL Inspection. قرار الفهرسة لمحرك البحث؛ لا ضمان لموعد أو ترتيب.
7. إنشاء GA4 وWeb stream، ووضع معرّف `G-...` الحقيقي في `NEXT_PUBLIC_GA_MEASUREMENT_ID`. **عطّل Enhanced measurement بالكامل** في هذا الـstream؛ نعتمد الأحداث المحددة في الكود لتجنب قياس التاريخ والنماذج والروابط تلقائيًا أو تكرار مشاهدة الصفحة. لا تنشر المعرّف قبل ضبط الحساب وفهم سياسة البيانات.
8. اختبار قبول ورفض الإحصاءات وتغيير الاختيار، والتنقل داخل الصفحات العامة، ثم الدخول إلى لوحة الإدارة والرجوع. تحقق في Tag Assistant وDebugView من عدم وجود بيانات شخصية أو query string أو صفحات إدارة، ومن حدث page_view واحد لكل زيارة. أبقِ جمع الإعلانات والإشارات الإعلانية مغلقًا ضمن النطاق الحالي.
9. راجع Core Web Vitals في PageSpeed وSearch Console عند وجود بيانات ميدانية كافية. اختبارات Chromium المحلية لا تثبت LCP أو INP أو CLS لشريحة الزوار المئوية 75.
10. بعد أول 28 يومًا، صدّر بيانات Search Console وGA4 الرسمية، وافصل بحث البراند عن بحث الحل، والسعودية والأجهزة، ثم اختر ثلاث خطوات للشهر التالي. استيراد تقارير فعلية أو ربط API قراءة من الخادم مرحلة تالية بعد توفر الحسابات والبيانات.

## التشغيل المستمر

عند كل مقال: حدّد السؤال والجمهور، راجع المصدر وحدود المنتج، اختر حلًا مرتبطًا، أضف روابط مفيدة، ثم افحص النسخة المنشورة كزائر وحدد موعد المراجعة. الحفظ التلقائي لا ينشر التعديلات.

أسبوعيًا: راجع تنبيهات الفهرسة والروابط والطلب على الموبايل، واجمع سؤالًا من المبيعات. شهريًا: قارن آخر 28 يومًا بالفترة السابقة مع مصدر وتاريخ البيانات، وراجع أفضل الصفحات والطلبات المؤهلة. لا تعتبر فتح واتساب طلبًا وصل أو صفقة. لا تغيّر تاريخ المقال لتبدو المعلومات أحدث دون تعديل فعلي.

## التحقق المحلي

`npm run test:articles` للتحقق من بنية المحتوى والروابط والعناوين والموجز. `npm run test:seo:http` يتحقق من المقالات الثمانية وHTML والبيانات المنظمة والخريطة والترقيم والتحويلات وحجز الروابط وحماية الصور وإلغاء النشر والتواريخ. `npm run test:articles:http` و`npm run test:articles:browser` يغطيان دورة المحرر والمصادقة وRLS والواجهة. الخادم الافتراضي لهذه الاختبارات `http://127.0.0.1:3012`، ويمكن ضبطه عبر `AUTH_TEST_BASE_URL`.

أُبقيت المقالات والمسودات السابقة، وتُحذف سجلات الاختبار التي تنشئها الاختبارات فقط. لا تزال هناك خطوات تتطلب أصل الدومين وحساب Google: لم ننفذ شراء دومين أو نشرًا خارجيًا أو إثبات DNS أو نختلق بيانات زيارات وترتيب.

### نتائج التحقق في هذه المرحلة

- نجح build الإنتاجي وTypeScript وESLint.
- نجح 11 اختبارًا للمحتوى وإعداد الفهرسة، وخمسة اختبارات لصلاحيات حسابات الإدارة.
- نجحت اختبارات HTTP للمحرر، واختبارات SEO على خادم التطوير ونسخة الإنتاج المحلية: HTML وcanonical وJSON-LD والخريطة وترقيم صفحة ثانية فعلية، وثبات تاريخ المحتوى، وتحويل الروابط وحجزها، و404 وإخفاء الصور بعد إلغاء النشر.
- نجحت اختبارات Chromium الأربعة للمحرر وRLS وتخطيط الإدارة والتفاف النص حول الصور. وأكدت المراجعة البصرية للحلول والباقات والمكتبة والمقال وقسم SEO سلامة عرض اللابتوب 1366×768 والموبايل 390×844 دون تجاوز أفقي أو أخطاء JavaScript.
- في عينة واحدة، حجم أصل PNG كان 132,494 بايت مقابل 5,782 بايت لمقاس WebP بعرض 320 بكسل؛ هذا قياس لصورة ومقاس محددين، وليس نتيجة أداء للموقع أو بيانات Core Web Vitals ميدانية.
- الحالة النهائية بعد تنظيف سجلات الاختبار: ثمانية مقالات منشورة، والمسودتان السابقتان محفوظتان، وخمسة حسابات إدارة فعالة. لا توجد الملاحظات التحريرية الخاصة في جدول النسخ العامة، وRLS مفعلة على سجل الروابط.
