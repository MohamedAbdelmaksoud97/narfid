# مقالات نرفد — المسار المختصر

الغرض: إنجاز المقال عبر المكونات ومسار النشر الموجودين، والاستفادة من مشكلات التنفيذ السابقة بدل إعادة اكتشافها. هذه المهارة لا تمنح إذن نشر جديدًا أو تغيير بيانات خارج نطاق الطلب.

## حدّد المسار قبل العمل

- **صياغة نص فقط:** اكتب المحتوى المطلوب؛ لا تشغّل Supabase أو اختبارات الموقع لمجرد كتابة النص.
- **إضافة أو تعديل مقال في المنصة:** استخدم المحرر أو API الحاليين. احفظ كمسودة عندما يكون المطلوب كتابة أو إعداد مسودة؛ انشر عندما يشمل الطلب أو تفويض الجلسة النشر بالفعل، دون طلب تأكيد مكرر.
- **دفعة مقالات:** استخدم نفس التحقق والرفع والنشر في أداة تشغيل قصيرة عند الحاجة. لا تُنشئ صفحة Next.js أو محررًا أو migration لكل مقال.
- **تعديل سلوك المحرر أو النشر:** اقرأ مصدر الجزء المتأثر ووثائق Next.js المحلية ذات الصلة، ثم نفّذ الاختبارات المناسبة للتغيير.

قبل تخطيط المقال أو كتابته أو تحريره، اقرأ [مهارة SEO نرفد](../narfid-seo/SKILL.md) لاختيار النية والعبارة والوجهة ومنع تكرار الموضوعات، و[مهارة NARFID](../narfid/SKILL.md) للمحتوى والادعاءات وحدود المنتج. ارجع إلى بحث الموضوع وتدقيق الوظيفة المطلوبة فقط؛ لا تعِد بحث الحملة أو فحص مشروع GO كله لكل مقال. عند التعامل مع Supabase اتبع مهارته، ومع SQL أو تغيير المخطط اتبع أيضًا مهارة Postgres المطلوبة في البيئة.

## تجهيز المحتوى مرة واحدة

حدّد سؤال القارئ ودوره ونيته، ثم اكتب إجابة عملية بأمثلة مفهومة وروابط تخدمها. استخدم حدود المنتج المثبتة؛ ميّز المثال التوضيحي عن نتيجة عميل. لا تفرض عدد كلمات أو أقسام أو كثافة كلمات ثابتة.

قارن السؤال بالمقالات الحالية، بما فيها المسودات، وبخريطة الوجهات قبل إنشاء سجل جديد. ملفات الحملة نسخة مصادر مؤرخة وليست بديلًا لقراءة آخر تعديل في المحرر. حدد فائدة جديدة واضحة، أو حسّن المقال القائم عندما يخدم النية نفسها. اربط المصادر وتاريخ فحصها ومبرر اختيار النية بالملاحظات التحريرية، مع إسناد عام داخل النص حين يحتاجه القارئ. اجعل العنوان والملخص وحقول SEO خاصة بالمقال، واستخدم CTA مناسبًا لعرض توضيحي دون وعد ترتيب أو نتائج أعمال.

عند طلب مقالات جديدة، طبّق قرار إعادة استخدام البحث أو البحث عن فرص جديدة من [مرجع التخطيط](../narfid-seo/references/editorial-planning.md)، واحفظ أي عبارات وأبحاث جديدة في سجل المهارة المشار إليه هناك. اختر المحور والجمهور والتصنيف من واقع الجرد؛ التصنيفات التحريرية المقترحة لا تعني أنها موجودة في قاعدة البيانات. لا تُجبر كل المقالات على تصنيف واحد أو قالب بيع واحد.

المقال التعليمي للمدير أو الموظف يجب أن يقدم إجراءً أو نموذجًا كاملًا يمكن استخدامه دون نرفد. الربط بالمنتج وCTA اختياريان حسب النية والسياق؛ قد تكفي خطوة عملية أو إحالة إلى دليل آخر. يمكن أن يكون `related_solution: null` عند عدم وجود حل مناسب. لا تنسخ خاتمة عرض المنتج الآلية في مساعد الحملة القديمة كمتطلب لكل مقال جديد، ولا تنسب لنرفد وظيفة غير مثبتة لمجرد إيجاد رابط تجاري.

- خزّن المتن كـTiptap JSON، لا HTML أو Markdown خام داخل `content`.
- عنوان المقال يظهر H1 من القالب. `heading` داخل المستند بـ`attrs.level: 1` يظهر H2، وبـ`2` يظهر H3.
- الرابط الداخلي يقبل مسارًا مثل `/solutions/memberships` داخل علامة `link`؛ لا يحتاج الدومين النهائي. لا تستخدم رابطًا يبدأ بـ`//`.
- الهوية العامة الحالية للكاتب `public_author_slug: "nerved-team"`؛ حساب الحفظ الإداري ليس شخصية كاتب عامة.
- اضبط الحل المرتبط والسؤال والجمهور والنية والملاحظات وموعد مراجعة مناسب. لا تنسخ تاريخ مراجعة دفعة الإطلاق القديمة تلقائيًا لمقال جديد.
- الحقول الأساسية: `title`, `slug`, `excerpt`, `content`, `category_id`، `tags`, `direction`, `cover_image_url`, `cover_image_alt`, `seo_title`, `seo_description`. استعمل `null` للغلاف والتصنيف غير المختارين، وسلاسل فارغة لحقول SEO الاختيارية.
- الحدود الحالية المهمة: العنوان 200، الملخص 500، عنوان البحث 70 ووصفه 180 حرفًا؛ حتى 10 وسوم، كل منها 40 حرفًا. هذه حدود التطبيق وليست قواعد ترتيب Google. استخرج التصنيف من قاعدة البيانات بدل اختلاق UUID.
- في الاستيراد البرمجي، مرّر البيانات إلى `validateFields`، وإلى `validatePublication` قبل النشر. `PATCH` يستقبل مجموعة الحقول كاملة؛ ابنها من أحدث بيانات المقال للحفاظ على الحقول الأخرى.

مثال لبنية المتن فقط:

```json
{
  "type": "doc",
  "content": [
    { "type": "heading", "attrs": { "level": 1 }, "content": [{ "type": "text", "text": "راجع سياسة التجديد" }] },
    { "type": "paragraph", "content": [{ "type": "text", "text": "حل الأعضاء والاشتراكات", "marks": [{ "type": "link", "attrs": { "href": "/solutions/memberships" } }] }] }
  ]
}
```

## حفظ الصور والمقال دون إعادة بناء النظام

للـAPI استخدم جلسة مجلس إدارة فعلية وCookie، و`Origin` المطابق لأصل الخادم؛ طلبات JSON تحتاج `Content-Type: application/json`. لا تعالج 403 بتعطيل فحص المصدر أو RLS.

| الخطوة | الطلب والنتيجة |
| --- | --- |
| الإنشاء | `POST /api/board/articles` بجسم `{ "id": UUID }`؛ إعادة نفس المعرّف آمنة عند ضياع الرد |
| الصورة إن لزمت | `POST /api/board/articles/{id}/images` كـFormData بالحقل `file`؛ أعد استخدام `url`, `width`, `height` من الرد |
| الحفظ | `PATCH /api/board/articles/{id}` بجسم `{ "revision": latestRevision, "fields": fullFields }` |
| النشر أو إلغاؤه عند التفويض | `POST /api/board/articles/{id}/publish` بجسم `{ "revision": latestRevision, "action": "publish" }` أو `unpublish` |

استخدم `article.revision` من آخر رد، ونفّذ عمليات المقال الواحد بالتتابع. عند 409 أعد قراءة السجل وقارن التغييرات؛ لا تكرر حفظ نسخة قديمة أو تستبدل عمل المستخدم بالقوة.

النشر نفسه يغيّر المراجعة؛ لا تستخدم رقم ما قبل النشر لعملية لاحقة. إذا ضاع الرد، اقرأ السجل والنسخة المنشورة وقارن المحتوى والحالة قبل المحاولة مجددًا.

للأداة البرمجية الموثوقة يمكن إعادة استخدام نمط عميل Supabase الموثق في سكربت الدفعة: حساب مجلس إدارة نشط، تحقق الحقول، ثم RPC `publish_article` مع `article_id` و`expected_revision`. لا تكتب يدويًا في `article_publications` لتجاوز دورة النشر. اقرأ بيانات الاعتماد من ملفاتها المحلية دون طباعتها أو نسخها داخل الكود.

### استكمال الحملة أو إنشاء دفعة جديدة

حملة `content/seo-campaign` المؤرخة 2026-10-21 لها 20 معرّفًا ورابطًا ثابتًا، وmanifest لبصمات المصادر والصور. شغّل الأوامر من جذر المشروع:

```powershell
# تحقق محلي من المصادر والحقول والصور والبصمات؛ لا يكتب في قاعدة البيانات
node --import=tsx scripts/import-seo-campaign.ts

# بعد مراجعة تعديلات المصادر فقط: تحديث manifest المحلي
node --import=tsx scripts/import-seo-campaign.ts --prepare

# لاستكمال النشر المصرح به فقط؛ ليس أمر تحقق
node --env-file=.env.local --import=tsx scripts/import-seo-campaign.ts --apply
```

السجل والقفل وجرد ما قبل الاستيراد داخل `.private/seo-campaign`؛ لا تدخل Git. الأداة تتحقق من ملكية السجلات والمعرّفات والروابط وبصمات المحتوى والصور والمراجعات، وتستخدم التحقق والتخزين الخاص وRPC النشر المعتاد. حافظ على هذه الضمانات عند صيانتها؛ لا تتجاوز التعارض لتكملة الدفعة.

إعادة التشغيل تتخطى المقالات المكتملة وتحفظ تعديل المحرر أو إلغاء النشر اللاحق. تعديل `articles.json` أو تشغيل `--prepare` لا يحدّث مقالًا منشورًا تلقائيًا؛ استخدم المحرر أو API مع أحدث مراجعة. لا تحذف سجل الاستكمال لإجبار الكتابة. عند قفل متروك بعد انقطاع، تحقق أولًا من انتهاء عملية الاستيراد قبل إزالة القفل فقط.

لحملة أخرى أنشئ مصادر وmanifest وسجل استكمال مستقلين مع إعادة استخدام مساعدات التحقق والنشر. لا تعِد توظيف دفعة الثمانية الأصلية أو معرّفات دفعة العشرين، ولا تغيّر قيود عدّهما لتمرير حملة مختلفة. اقرأ حالة النشر الحية من `articles` و`article_publications`، لا من حالة الاستيراد المحلية.

### الصور واللقطات

- **تفضيل الأغلفة المعتمد:** أغلفة المقالات مرتبطة بموضوع كل مقال ومتنوعة بين الاستقبال والحجوزات والمطبخ والمخزون والإدارة. اتبع توجيه الصور للسوق السعودي في `AGENTS.md`: الأشخاص مرحّب بهم بملامح عربية وملابس مناسبة للسوق السعودي؛ وتُستخدم أماكن وتفاصيل مرتبطة بالموضوع عند عدم توفر صورة بشرية مناسبة، دون تحويل التوجيه لمنع الأشخاص. لا تجعل لقطة واجهة النظام غلافًا افتراضيًا؛ يمكن إضافة لقطة صغيرة حقيقية بهوية نرفد عند الحاجة. لا تستخدم هوية GO أو بيانات عميل في الأغلفة. الصور المولّدة أمثلة توضيحية، وليست شهادات أو صور عملاء حقيقيين؛ يُذكر مصدرها في التوثيق والوصف المناسب دون عبارات مطبوعة فوق الصورة. يحتفظ المشروع بنسخ WebP محسّنة ومصدر الصورة وترخيصها (أو prompts للصور المولّدة) في `content/article-covers`، والنشر يمر بمخزن المقالات الخاص كالمعتاد.

- أغلفة حملة SEO الإضافية ومصادرها في `content/seo-campaign/covers`، وتعيد الحملة استخدام أغلفة مناسبة من `content/article-covers`. افحص الصورة بصريًا وراجع مصدرها وترخيصها؛ وجودها في مستودع قديم وحده لا يثبت ملاءمتها لموضوع جديد. اكتب وصفًا بديلًا عربيًا يصف الصورة دون حشو العبارة المستهدفة.
- ارفع PNG/JPG/WebP/GIF صالحًا، حتى 5 MiB. المسار المقبول هو `/media/articles/{articleUUID}/{fileUUID}.ext`؛ لا تضع صورة مباشرة في `public` لتجاوز حماية المسودة.
- الغلاف وصور المتن يحتاجان وصفًا بديلًا عند النشر. خزّن الأبعاد من نتيجة الرفع، واستفد من مسار المقاسات الموجود بدل بناء محسن صور جديد أو cache عام للمسودات.
- عند الحاجة للقطة من GO، ابدأ بدليل الصور `../go/go/public/guide/screenshots` بالنسبة لجذر `narfid`؛ لا يلزم تشغيل النظام من الصفر إذا وُجدت لقطة مناسبة.
- نقطة بدء سبق فحصها: إعداد الباقات `17-system-packages.png`، موارد الحجز `34-system-bookable-resources.png`، قائمة اليوم `11-restaurant.png`، ومخزون المنتجات `44-system-retail-inventory.png`. افحص النسخة الحالية بصريًا قبل استخدامها؛ اسم الملف لا يضمن خلوه الدائم من بيانات الأعضاء.
- تجنب الأسماء والجوالات والهوية والفواتير الشخصية. وضّح أن اللقطة من النظام المرجعي Go Fitness حين تحمل هويته؛ لا تنسب أرقام الشاشة إلى نتائج نرفد. مجلد GO مرجع للقراءة فقط.

## أخطاء حدثت فعلًا وكيف نتجنب تكرارها

| الحالة | التصرف المختصر |
| --- | --- |
| `Top-level await ... cjs output format` | المشروع لا يعلن ESM لكل ملفاته. اتبع `async function main()` مع استدعاء يعالج الخطأ كما في سكربت الدفعة؛ لا تغيّر نوع المشروع كله لتشغيل أداة واحدة. أدوات TypeScript القائمة تعمل عبر `node --env-file=.env.local --import=tsx ...`. |
| انتهاء جلسات أخرى أثناء أداة رفع أو اختبار | `signOut()` الافتراضي قد ينهي جلسات أخرى للحساب. لإنهاء جلسة الأداة فقط استعمل `signOut({ scope: "local" })`، ولا تشغّل خروجًا عامًا ضمن تنظيف مهمة محتوى. |
| `npm run seo:seed` لا يحدّث مقالًا منشورًا | مقصود: الأمر خاص بدفعة الإطلاق وله سجل `.private/seo-seed-state.json`. ليس ناشرًا عامًا ولا أمر تحقق فقط. لا تحذف السجل ولا تُجبره على الكتابة فوق مقال عُدّل أو أُلغي نشره؛ استخدم مسار تحرير المقال الحالي. |
| المقال أُلغي نشره لكن استجابة الصفحة 200 | `notFound()` بعد بدء بث Suspense قد يصل متأخرًا. يوجد حسم مسبق في [proxy.ts](../../../proxy.ts) و[مسار عدم التوفر](../../../app/article-unavailable/page.tsx) الذي يستدعي `notFound()` تزامنيًا. لا تنقل هذا الحسم داخل الجزء المبثوث؛ اختبر HTTP الفعلي. |
| رسالة حفظ عامة من Supabase | افحص الخطأ الفعلي مرة بصورة لا تكشف بيانات حساسة؛ فرّق بين فشل تحقق الحقول، وتعارض revision، ومخطط غير مطبق، وصلاحية مفقودة. اتبع تشخيص مهارة Supabase بدل تكرار الطلب أو توسيع الصلاحيات. |

**فقط إذا احتاجت المهمة تغيير قاعدة البيانات:** إنشاء ملف migration أو تسجيله لا ينفذ SQL. في الأداة الحالية `scripts/article-db.mjs path/to/migration.sql` ينفذ الملف، و`--record path/to/migration.sql` يؤرشفه فقط ويحافظ على الإصدار المولد بواسطة CLI. اتبع سير migrations المعتمد، ثم تحقق من الأعمدة/الدالة فعليًا ومن تطابق التاريخ مع اسم الملف. لا تكرر التنفيذ عشوائيًا إذا ضاع الرد. وعند تعديل دالة النشر، المقارنة بالسجل الكامل تستخدم alias صريحًا مثل `current_publication`؛ كتابة `to_jsonb(public.article_publications)` سببت `42P01`. هذه حالة صيانة، وليست خطوة مطلوبة لإضافة مقال.

## تحقق بقدر التغيير ثم انتهِ

- **محتوى فقط:** تحقق من الحقول، وعدم التكرار، والروابط والصور. للمقال المنشور افتحه كزائر وتأكد من النسخة المقصودة وظهوره في المكتبة والخريطة؛ للمسودة تأكد من بقائها خاصة. لا تعِد النشر أو إلغاءه لمجرد اختبار مقال المستخدم دون داعٍ.
- **تعديل كود المقالات:** ابدأ بـ`npm run test:articles`، ثم فحص السلوك المتأثر. استخدم HTTP/Chromium عند تغيير النشر أو الصور أو العرض؛ لا تُعد كامل مجموعة الاختبارات لكل تصحيح نصي.
- **تعديل مصادر أو مساعدات الحملة:** شغّل `npm run test:seo:campaign` وأمر الاستيراد دون `--apply` أعلاه. اختبار `tests/browser/seo-campaign.spec.ts` يعتمد على وجود مقالات الحملة وبيانات الجرد المحلية وحساب اللوحة؛ ليس اختبارًا عامًا لإضافة مقال منفرد. لا تعِد استيراد الحملة لتجهيز اختبار غير مطلوب.
- **تعديل النشر/الخصوصية/الروابط:** اختبارات `test:articles:http` و`test:seo:http` و`test:articles:browser` تغطي الحالات القائمة. تنشئ سجلات اختبار حقيقية وتنظفها؛ استخدمها لهذا النوع من التغيير، لا كخطوة إجبارية لكتابة مقال. عنوان الاختبار الافتراضي `http://127.0.0.1:3012` وقابل للضبط عبر `AUTH_TEST_BASE_URL`.
- بيانات المسودة في `articles` منفصلة عن `article_publications`. الحفظ لا يحدث المنشور؛ وتعديل الملاحظات الداخلية لا ينبغي أن يغير تاريخ المحتوى العام. الروابط القديمة محجوزة وتحوّل إلى الرابط المنشور الحالي، وإلغاء النشر يخفيها والصور ومقاساتها.
- اذكر في النتيجة: ما أُضيف أو عُدّل، هل هو مسودة أم منشور، ورابطه والتحقق المنفذ. حدّث قسم SEO عندما تشمل المهمة متابعة المرحلة؛ لا تعامل أعداد تقرير قديم كأعداد ثابتة للموقع.
